# Riviera Production Sheet Template Library v2

**Status:** Active source addendum for Riviera SOP Master Index v7  
**Date:** 2026-06-16  
**Use for:** Future Riviera food-only prep sheets, production sheets, run sheets and kitchen PDFs.

---

## 0. Purpose

This file prevents layout drift.

Use these templates before writing any future event prep sheet. The content changes event by event, but the sheet structure, card order, command style, greyscale hierarchy, owner-first task cards, and ready-to-send logic stay consistent.

Kitchen sheets are food-control documents only. They show what to prep, cook, cool, season, fire, pack, deliver and serve.

---

## 0A. v2 prep-list baseline update

When the user asks for a prep list, run sheet or production sheet, assume ordering is complete and stock has arrived unless the user asks for an order list.

Do not include:

```text
- Place orders
- Supplier email tasks
- Still-needed order ledgers
- Coldroom space allocation
- Rack allocation
- Make-room / clear-shelf cards
```

Allowed where useful:

```text
Sort delivered stock by event/use.
Keep GF/DF/dietary items separate.
```

If the user asks for the prep list from a specific day, start from that day and omit earlier completed/order days.

## 1. Universal sheet order

Use this order unless the user specifically asks for something else.

```text
1. EVENT / WEEK SNAPSHOT
2. WHAT WE ACTUALLY PREP / QUANTITY CHECK
3. FILLING SUMMARY, if sandwiches, wraps, croissants, brioche, focaccia, boxes or lunch items are involved
4. DIETARY ACTION, if any dietary affects production
5. FOOD TIMES / SERVICE TIMELINE
6. START HERE / DO NOT START YET / DELIVERED STOCK SORT, where useful
7. PRODUCTION CARDS BY DAY
8. EVENT-DAY FIRE / PACK / SEND CARDS
9. READY TO SEND / READY TO SERVE GATE
10. POST-EVENT DEBRIEF
```

Quantities come before food times.

---

## 2. Universal visual rules

```text
PAGE: A4 portrait
DESIGN: black / white / grey only
LAYOUT: full-width stacked cards only
BODY FONT: Arial, Helvetica or Liberation Sans
CARD BODY: minimum 13 pt
CARD TITLE: 16-18 pt bold
DAY HEADING: 20-22 pt bold
MAIN TITLE: 24-28 pt bold
```

Every food-action block stays inside a visible bordered card. Do not remove card frames. Do not use side-by-side cards. If a card does not fit, move it to the next page.

---

## 3. Universal card grammar

Active cards start with owner + command action.

```text
ASH | Start **vegetable prep**
DAN | Fire **beef fillet**
BOTH | Pack **wake delivery**
ASH | Build **corporate fruit boxes**
DAN | Finish **sauces**
```

Use direct verbs:

```text
Make / Start / Begin / Pull / Fire / Reheat / Cook / Cool / Portion / Allocate / Pack / Fold / Mix / Marinate / Brine / Cryovac / Finish / Send
```

Inside production cards, the food item being prepped is bold.

## 4. SINGLE EVENT — delivery catering

Use for corporate deliveries, wake deliveries, platter deliveries, breakfast drops, lunch boxes and general drop-and-run catering.

### Required structure

```text
EVENT SNAPSHOT
- Event:
- Date:
- Delivery time:
- Location:
- Guest count:
- Event type:
- Menu:
- Dietaries:

WHAT WE ACTUALLY PREP
- **Item** — exact quantity / platter count / box count
- **Dietary item** — exact quantity / replacement note

FILLING SUMMARY, if relevant
- Ham cheddar
- Beef horseradish
- Smoked chicken dill
- Roast pumpkin feta pesto

DIETARY ACTION
- GF guest x 1 — make 1 GF sandwich box / no croissant unless confirmed

FOOD TIMES
- Delivery due:
- Hot food fire/send window:
- Cold food packed by:

START HERE
- First 3-5 food actions only

PRODUCTION CARDS BY DAY
- Owner-first full-width cards

READY TO SEND
- All food counted
- Hot/cold packed
- Sauce packed
- Dietary packed separately
- Driver handoff clear
```

### Delivery card examples

```text
ASH | Build **sandwich platter** — 24 points
Make fillings first. Assemble, cut into quarters, pack flat. Keep dietary separate if required.

DAN | Fire **hot nibbles** — 48 pieces
Reheat/fry to correct finish. Season hot. Pack into hot box with sauce.

BOTH | Send **delivery order**
Count boxes before driver leaves. Use only the event allocation shown in the quantity check.
```

## 5. SINGLE EVENT — onsite plated dinner

Use for weddings, private dinners, gourmet club, alternate drops and plated corporate dinners.

### Required structure

```text
EVENT SNAPSHOT
WHAT WE ACTUALLY PREP
ALTERNATE-DROP COUNT, if relevant
DIETARY ACTION
FOOD TIMES / RUN SHEET
START HERE
DAY-BEFORE PRODUCTION
DAY-OF PRODUCTION
SERVICE / FIRE CARDS
READY TO SERVE GATE
DEBRIEF
```

### Count logic

```text
Guest count + 9% buffer = total production target
Dietaries are included inside total target
Normal mains are reduced evenly when dietary alternates are added
```

### Plated card examples

```text
DAN | Marinate + cryovac **beef fillet** — 40 portions
Season, marinate, cryovac at Roscoes if needed. Do not pre-cook steak unless event plan says so.

ASH | Start **vegetable garnish** — 80 portions
Prep vegetables by course. Keep garnish and dietary portions separate.

DAN | Finish **tarragon cream** — 2.4 L
Taste after reheating. Adjust salt, lemon and tarragon before service.

BOTH | Plate **alternate drop mains**
Use allocation exactly. Do not let one main eat into the dietary buffer.
```

## 7. SINGLE EVENT — offsite buffet / carvery

Use for offsite hot service, carvery, feast delivery and sous-vide bain reheats.

### Required structure

```text
EVENT SNAPSHOT
WHAT WE ACTUALLY PREP
OFFSITE HOT COUNT + BUFFER
DIETARY ACTION
FOOD TIMES
START HERE
ROSCOS CRYOVAC WINDOW, if needed
DAY-BEFORE SOUS-VIDE / COOK-AHEAD CARDS
DAY-OF REHEAT / PACK / SEND CARDS
OFFSITE READY GATE
DEBRIEF
```

### Offsite rules

```text
- Suitable proteins are marinated/brined and cryovacced where practical.
- Cryovac happens at Roscoes.
- Allow 30 minutes for Dan or Ash to leave Riviera, go to Roscoes and seal.
- Cryovacced non-steak items are cooked one day in advance where suitable.
- Steak remains marinated/cryovacced and is not pre-cooked unless specified.
- Offsite cryovacced items are reheated/held in sous-vide bains where practical.
```

### Offsite card examples

```text
DAN | Brine + cryovac **roast chicken** — 60 portions
Brine/marinate. Portion into bags. Roscoes cryovac window: 30 minutes.

ASH | Portion **offsite graze** into PC containers
Portion cheeses, meats, olives, crackers, bread/focaccia, dips, fruit and garnish into PC containers for the event.

DAN | Reheat **cryovac lamb** in sous-vide bain
Use event allocation only. Hold controlled. Season/finish after opening where needed.
```

## 11. MULTI-EVENT — delivery-heavy week

Use when multiple deliveries share production windows.

### Required structure

```text
WEEK SNAPSHOT
EVENT INDEX
WHAT WE ACTUALLY PREP — BY EVENT
DELIVERED STOCK SORT — optional, short, only if useful
SHARED PREP — ONLY IF TRUE OVERLAP
DIETARY ACTIONS — BY EVENT
FOOD TIMES — BY EVENT
DAY-BY-DAY PRODUCTION CARDS
EVENT-DAY READY TO SEND GATES
DEBRIEF
```

### Delivered stock sort block

Use this only if it helps multi-event separation. Keep it short.

```text
SORT DELIVERED STOCK — quick pass
- Sort delivered stock by event/use.
- Keep GF/DF/dietary items separate.
```

Do not add coldroom/rack allocation, shelf planning or make-room tasks unless the user specifically asks for storage planning.

### Shared allocation card

```text
ASH | Make **roast pumpkin base** — 10 kg raw
Roast plain. Chill flat.

PORTION / ALLOCATE AFTER PRODUCTION:
- Event A — 2 kg
- Event B — 3 kg
- Event C — 4 kg
- Buffer — 1 kg
```

No explanation unless there is a real risk.

## 15. MULTI-EVENT — mixed nightmare week

Use when multiple event types overlap: corporate, wake, wedding, offsite, tapas.

### Required structure

```text
WEEK SNAPSHOT
EVENT INDEX
MAJOR RISKS — food-only
DELIVERED STOCK SORT — optional, short, only if useful
WHAT WE ACTUALLY PREP — BY EVENT
SHARED PREP — compact allocation only
DIETARY ACTIONS — by event
FOOD TIMES — by event
PRODUCTION DAYS
EVENT DAY BANNERS
READY TO SEND / READY TO SERVE GATES
DEBRIEF
```

### Nightmare week rule

Keep the sheet functional. Do not try to explain the whole event. Show what food is due, what to prep, what to fire, what to pack, and what allocation belongs to which event.

## v2 changelog

- Universal sheet order now uses optional **Delivered Stock Sort** instead of **Coldroom Ready**.
- Prep templates assume orders are placed and stock has arrived unless ordering is requested.
- Order/still-needed sections are removed from default prep-list structure.
- Coldroom/rack allocation cards are removed from default templates.
- Sheets start from the user-requested day when specified.
